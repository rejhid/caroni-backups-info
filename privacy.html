Google Drive integration

Privacy policy

Effective October 3, 2026

Caroni Backups is a personal utility maintained by the household account owner. This policy covers its encrypted backup workflow and Google Drive authorization.

What the integration accesses

The integration requests the Google Drive permission to view and manage files. That permission is broader than the backup folder: Google does not restrict this grant to a single folder. The workflow is configured to operate on the owner’s designated backup folder and retention archive.

It uses folder identifiers, file names, sizes, hashes and encrypted file contents to locate the destination, upload backups, verify them, restore them and manage retention. It does not request Gmail, Contacts or Calendar access.

How the data is used

Drive access is used for backup and recovery: creating and verifying encrypted backup files, reading them for restoration, and archiving or deleting obsolete backup objects. Unrelated Drive files are not used for analytics, advertising or model training.

Where data is stored

Database dumps and app files are encrypted locally with restic before upload. Google Drive stores the encrypted repository; Google can still see the account, object names, sizes and upload activity. The repository password is held separately and is not uploaded to Drive.

The OAuth client credentials and refresh token are held in protected configuration on the owner’s host. They are not included in the backup repository or these public pages. Cloud API requests and backup transfers use verified HTTPS.

Sharing and monitoring

The workflow sends encrypted backup objects to the Google Drive account authorized by the owner. It sends empty success or failure heartbeat requests to Healthchecks.io for operational alerts; these do not contain Drive file contents, financial records, credentials or logs.

Google user data is not sold, used for advertisements or used to train AI models. Its use is limited to the backup and recovery features described here, consistent with the Google API Services User Data Policy, including its Limited Use requirements.

Retention and deletion

The default snapshot policy retains 14 daily and 8 weekly backups. Obsolete repository objects are moved to a separate deletion archive, retained for 30 days before cleanup. Restic snapshots share encrypted objects, so removing a snapshot does not necessarily remove every object it referenced.

The owner controls the backup folders and can delete them in Drive. Deleted files may remain in Google’s Trash or other provider retention systems until removed according to Google’s policies. Revoking authorization stops future access; it does not delete existing backup files.

Your control

You can revoke this integration in your Google Account’s third-party connections settings and stop the local backup schedule. To remove local authorization, remove its protected rclone configuration. Keep an independent copy of any backup you still need before deleting backup data or its decryption password.

These pages

These static pages contain no sign-in forms, JavaScript, tracking cookies or analytics. The chosen website host may process ordinary request information, such as IP addresses, under its own privacy policy. No Google credential or household financial record is part of the website.

Contact and changes

For questions, contact the household maintainer through the support email shown on Google’s consent screen. This policy will be updated before the integration introduces a materially different use of Google data; any additional permission will require renewed consent.
